# 11. A web browser

`tools/browser/browser.omg` is a web browser:

```sh
omg --build tools/browser/browser.omg browser
./browser https://en.wikipedia.org/wiki/Web_browser
```

It fetches a page over HTTP or HTTPS, reads its HTML and CSS, lays it
out, draws it with the fonts of the system, shows its pictures, and
lets you follow links, go back and forward, scroll, and fill in and
send forms. It does not run JavaScript.

Everything between the socket and the pixels is OMG: the HTTP client,
TLS and the ciphers and certificate checks under it, the HTML and CSS
parsers, layout, the reading of TrueType fonts and the drawing of
their letters, and the PNG, JPEG and GIF decoders. No library is
linked in and no other program is started. `browser` is one executable
of about 4.8 MB, and `--target windows-x64` gives the same thing for
Windows from Linux. The source is some 22,000 lines in twenty files.

## Using it

```sh
./browser                        # a start page
./browser example.com            # taken as https://example.com
./browser page.html              # a file; a directory is listed
./browser --screenshot out.png --size 1280x900 https://example.com
```

| Option | What it does |
| ------ | ------------ |
| `--size WxH` | The size of the window. 1100x760 when not given. |
| `--screenshot FILE` | Load the page, save a picture of the window as a PNG, and leave. No window is opened, so this works with no screen. |
| `--scroll N` | With `--screenshot`: the page scrolled down `N` pixels. |
| `--page-only` | With `--screenshot`: the page alone, without the bar and the scroll bar. |
| `--proxy HOST:PORT` | Go through an HTTP proxy (`CONNECT` for HTTPS). |
| `--ca-file FILE` | Trust the certificates in this PEM file as well as the built-in ones. |
| `--verbose` | Say on the terminal how long each step took. |

| Key | What it does |
| --- | ------------ |
| Ctrl+L | Put the cursor in the address bar. Enter goes there. |
| Alt+Left, Backspace | Back. |
| Alt+Right | Forward. |
| F5, Ctrl+R | Load the page again. |
| Escape | Stop, or leave the field being typed in. |
| Arrows, Space, PageUp, PageDown, Home, End | Scroll. The mouse wheel and the scroll bar do too. |
| Ctrl+V | Paste, in the address bar or a text field. |
| Ctrl+A, Ctrl+C | Select and copy the address. |
| Ctrl+Q | Leave. |

A click on a link follows it, and the status line at the bottom shows
where a link leads while the pointer is over it. Text fields, password
fields, text areas, check boxes, radio buttons, drop-down lists and
buttons work, and a form is sent with GET or POST as it asks. Cookies
are kept while the browser runs and forgotten when it closes.

When something goes wrong (no such host, a certificate that cannot be
trusted, a page that never answers) the browser shows a page saying
what happened, in words, and stays usable.

## The parts

Each is a file in `tools/browser/` that can be imported and used alone;
the comment at the top of each says how.

| File | Lines | What it is |
| ---- | ----- | ---------- |
| `browser.omg` | 1,750 | The window: the bar, history, scrolling, the mouse and keys, forms. |
| `url.omg` | 410 | Addresses: taking them apart, resolving a relative one, percent escapes. |
| `net.omg`, `io.omg` | 800 | The HTTP/1.1 client; `file:` and `data:` addresses. |
| `tls.omg` | 860 | TLS 1.3 and 1.2, the client's side. |
| `sha.omg` | 310 | SHA-256, SHA-384, SHA-512, HMAC, HKDF. |
| `aead.omg` | 690 | ChaCha20-Poly1305 and AES-GCM. |
| `pk.omg` | 770 | Big numbers; X25519, P-256 and P-384; ECDSA and RSA signature checks. |
| `x509.omg` | 690 | Certificates: reading them and deciding whether a chain can be trusted. |
| `roots.omg` | 250 | The certificate authorities trusted to begin with (generated by `mkroots.omg`). |
| `inflate.omg` | 400 | Unpacking gzip and zlib. |
| `html.omg`, `entities.omg` | 1,340 | From the bytes of a page to a tree of elements. |
| `css.omg` | 4,470 | Style sheets: parsing, matching, the cascade, computing values. |
| `layout.omg` | 4,280 | Where everything goes: blocks, lines, floats, tables, flexbox, grid. |
| `font.omg` | 1,090 | TrueType files: finding them, reading them, turning outlines into pixels. |
| `image.omg` | 1,500 | PNG, JPEG and GIF decoders. |
| `paint.omg`, `gfx.omg` | 2,040 | From boxes to a list of things to draw, and drawing them. |
| `util.omg` | 430 | Helpers for strings and bytes. |

A page goes through them in this order:

```
address ── url ──> net (tls) ──> bytes ── html ──> tree of elements
                                                         │  css: every element gets its style
                                                         ▼
window <── gfx <── display list <── paint <── boxes <── layout
```

The tree of elements is kept, so a change of the window's width or a
click on a check box starts again from the styles, not from the
network.

## Fetching

`net.fetch(address, method, body, content_type, referer)` returns a
dict: `status`, `headers` (names in lower case), `body` (a byte list),
`url` (the address after redirects) and, when `status` is 0, `error`
saying why nothing came back.

- HTTP/1.1, with connections kept open and used again for the next
  request to the same host.
- Bodies with a `Content-Length`, in chunks, or ended by the server
  closing; gzip and deflate unpacked.
- Redirects followed, up to twelve in a row, with the method changed
  to GET where the status says so.
- Cookies: `Set-Cookie` with `Domain`, `Path`, `Secure` and `Max-Age`
  or `Expires`, sent back to the hosts and paths they belong to.
- Through a proxy when asked: plain requests are handed to it, HTTPS
  goes through a `CONNECT` tunnel.
- `file:` reads from the disk and turns a directory into a page listing
  it; `data:` decodes the address itself.

## HTTPS

`tls.omg` is a TLS client. `tls.connect(socket, host)` does the
handshake and returns a connection to `read`, `write` and `close`, or
`false`, with `tls.error()` saying why.

| | |
| - | - |
| Versions | TLS 1.3 and TLS 1.2. Nothing older. |
| TLS 1.3 ciphers | ChaCha20-Poly1305, AES-128-GCM, AES-256-GCM. |
| TLS 1.2 ciphers | ECDHE with ECDSA or RSA certificates, and ChaCha20-Poly1305 or AES-GCM. |
| Key exchange | X25519, P-256, P-384. |
| Signatures checked | ECDSA with P-256 and P-384; RSA PKCS#1 and RSA-PSS; SHA-256, SHA-384, SHA-512. |
| Extensions | Server name, ALPN (`http/1.1`), extended master secret for 1.2. |

A second `ClientHello` is sent when the server asks for another curve,
keys are changed when the server asks (`KeyUpdate`), and a server that
falls back to 1.2 while claiming it could do better is refused, as the
standard requires.

The server's certificate has to stand up before a byte of the page is
asked for. `x509.check(certificates, host, now)` wants all of this:

- A chain of signatures from the server's certificate to one of the
  118 authorities in `roots.omg`, each one checked. Servers that send
  their certificates out of order, or send extra ones, are coped with.
- Every certificate in the chain within its dates.
- Every certificate above the server's own marked as an authority, and
  the limit an authority sets on the length of the chain below it kept.
- The host among the names the certificate is for. `*.example.com`
  covers `www.example.com` and nothing deeper; an IP address has to be
  listed as one.
- The certificate allowed to be used for a server, when it says what
  it may be used for.

What fails is said plainly, on the page shown in place of the one asked
for: "its certificate is for example.org, not for example.com", "its
certificate ran out on 1 March 2024", "its certificate was issued by
Some Authority, which this browser does not know".

`roots.omg` is Mozilla's list as packaged by the curl project. To bring
it up to date:

```sh
curl -O https://curl.se/ca/cacert.pem
omg tools/browser/mkroots.omg cacert.pem tools/browser/roots.omg
```

The big-number arithmetic keeps a number as a list of 28-bit pieces,
so that the product of two pieces and a few carries fit an OMG int,
and multiplies with Montgomery's method for every modulus. SHA-512
needs unsigned 64-bit words, which OMG does not have; it works on
pairs of 32-bit halves.

This is a browser's TLS, written to be read. It has not been reviewed
by anyone who breaks such things for a living, and its arithmetic
takes a different time for different numbers, which is a weakness on a
machine shared with an attacker. See also
[what is not there](#what-is-not-there).

## HTML

`html.parse(html.to_utf8(bytes, charset))` gives a document: a tree of
dicts, an element having `tag`, `attrs` and `kids`.

The parser forgives what browsers forgive. End tags may be missing (a
`<p>` ends at the next block, an `<li>` at the next `<li>`, table
parts close each other), elements without content (`<br>`, `<img>`)
need no slash, `<html>`, `<head>` and `<body>` appear whether written
or not, a stray end tag is passed over, and `<script>` and `<style>`
are read as raw text. All 2,125 named character references are known
(`entities.omg`), and pages in UTF-8, ISO-8859-1 and Windows-1252 are
read, the encoding taken from a byte order mark, the server's header
or `<meta charset>`.

A page with no `<!doctype>` is laid out in the old "quirks" manner in
the one way that matters most for old pages: tables do not take the
font and the alignment of what is around them.

## CSS

Style comes from the browser's own sheet, `<link rel="stylesheet">`,
`<style>`, `style="..."` and the old attributes (`bgcolor`, `width`,
`align`, `cellspacing`, `<font>` and the like), put together by the
rules of the cascade: origin, `!important`, specificity, order.

**Selectors**: tags, classes, ids, `*`, attributes (`[a]`, `=`, `~=`,
`|=`, `^=`, `$=`, `*=`, with `i`), the four combinators (space, `>`,
`+`, `~`), `:first-child`, `:last-child`, `:only-child`,
`:nth-child()` and its relatives, the `-of-type` family, `:root`,
`:empty`, `:not()`, `:is()`, `:where()`, `:link`, `:checked`,
`:disabled`, `:enabled`, and `::before` and `::after` with `content`.

**At-rules**: `@media` (width, height, orientation,
`prefers-color-scheme` and the common others), `@supports`, `@import`.
The rules inside `@layer` are used, in the order written.

**Values**: `px`, `em`, `rem`, `%`, `vw`, `vh`, `pt` and the other
absolute units, `calc()`, `min()`, `max()`, `clamp()`, `var()` with
custom properties, `inherit`, `initial`, `unset`; colours by name, in
hex, `rgb()`, `hsl()`, `currentcolor`, `light-dark()`.

**Properties**:

| | |
| - | - |
| Boxes | `display` (block, inline, inline-block, list-item, none, flex, inline-flex, grid, the table values, contents), `position` (static, relative, absolute, fixed, sticky), `float`, `clear`, `width`, `height`, their `min-` and `max-`, `box-sizing`, `margin`, `padding`, `border` and its parts, `inset` and `top` to `left`, `z-index`, `overflow`, `visibility`, `aspect-ratio` |
| Text | `font` and its parts, `line-height`, `color`, `text-align`, `text-indent`, `text-decoration`, `text-transform`, `letter-spacing`, `white-space`, `word-break`, `overflow-wrap`, `text-overflow`, `vertical-align` |
| Paint | `background` (colour, picture, repeat, position, size, linear gradients), `border-radius`, `opacity`, `object-fit` |
| Lists and tables | `list-style`, `border-collapse`, `border-spacing`, `caption-side`, `table-layout` |
| Flexbox | `flex` and its parts, `flex-direction`, `flex-wrap`, `justify-content`, `align-items`, `align-self`, `align-content`, `order`, `gap` |
| Grid | `grid-template-columns` (with `repeat()`, `fr`, `minmax()`), `grid-column`, `gap` |

A declaration that is not understood is dropped, as the standard says,
so an earlier one that is understood stays in force.

Matching does not try every rule on every element. Rules are indexed
by the id, class or tag at the right end of their selector, and an
element looks only at the rules filed under its own.

## Layout

`layout.build(doc)` turns the styled tree into a tree of boxes;
`layout.layout(root, width, height)` gives every box a place.

- **Blocks** stack down the page, with margins that collapse, `auto`
  margins that centre, and percentages of the box around them.
- **Lines**: text is cut into words, words are measured with the font
  and put on lines, with `text-align`, `white-space`, inline boxes with
  borders and padding of their own, inline-blocks and pictures in the
  line, and `vertical-align`.
- **Floats** go left and right and lines shorten to pass them; `clear`
  moves below them.
- **Tables** give columns widths from what the cells hold, in the
  automatic way and the fixed way, with `colspan` and `rowspan`,
  captions, and collapsed or separate borders.
- **Flexbox** in rows and columns, growing, shrinking, wrapping and
  aligning.
- **Grid** with columns from a template, items placed in order or on
  the columns they ask for. Rows are as tall as their content.
- **Positioned boxes**: relative, absolute against the nearest
  positioned box, fixed against the window. A sticky box stays where
  the flow puts it.

Boxes point at their children and never back at their parent. OMG
frees a value when the last reference to it goes, and two values that
point at each other would never go.

## Letters

`font.omg` looks in the system's font folders (`/usr/share/fonts`,
`/usr/local/share/fonts`, `C:\Windows\Fonts`) for TrueType files, and
for a `font-family` list picks the first family it has, in the weight
and slant asked for; `serif`, `sans-serif` and `monospace` stand for
whichever of the usual families is there. A letter's outline is lines
and quadratic curves. To draw it, the outline is scaled, the curves
are cut into short lines, and for every pixel the part of it inside
the outline is worked out exactly, which gives smooth edges without
drawing large and shrinking. Each letter at each size is drawn once
and kept. A character the chosen font lacks is looked for in the
others.

There is no hinting and no kerning, and fonts whose outlines are in
the CFF format (most `.otf` files) are passed over.

## Pictures

`image.decode(bytes)` returns `[width, height, pixels]`, four bytes a
pixel.

- **PNG**: every colour type and bit depth, palettes, transparency,
  interlacing.
- **JPEG**: baseline and progressive, grey and colour, every usual
  subsampling, restart markers.
- **GIF**: with transparency; the first frame of an animation.

Pictures are scaled to the size the page gives them, by averaging when
made smaller. A page is shown as soon as its text is laid out and its
pictures arrive after.

## Drawing

`paint.omg` walks the boxes in the order CSS lays down (backgrounds
and borders, then floats, then lines, then positioned boxes by
`z-index`) and writes a display list: fill this rectangle, draw this
run of text here, this picture there. `gfx.omg` carries the list out
into one int per pixel and hands that to `window_draw`. Scrolling
carries out the same list at another offset, with nothing laid out
again, and entries above or below the window are passed over.

The same list answers "what is under the pointer": the last entry
drawn at a point that belongs to a link or a form control.

## How fast it is

Measured on the machine the tests run on, with a built `browser`, from
the start of the program to the screenshot being written:

| Page | HTML | Total |
| ---- | ---- | ----- |
| example.com | 0.6 KB | 0.3 s |
| Hacker News, front page | 33 KB | 1.1 s |
| Wikipedia, "Web browser" | 417 KB | 2.9 s |

Of the Wikipedia page's time, 0.5 s is waiting for the page and its
style sheets. Working out styles (0.27 s) and laying out (0.1 s) are
done twice, when the text is in and again when the sizes of the
pictures are known. Most of the rest is fetching and decoding the
pictures one after another. `--verbose` prints these figures.

| Step | Speed |
| ---- | ----- |
| SHA-256 | 46 MB a second |
| ChaCha20-Poly1305 | 70 MB a second |
| AES-GCM | 38 MB a second |
| X25519 | 3.5 ms |
| ECDSA check, P-256 / P-384 | 13 ms / 37 ms |
| RSA check, 2048 to 4096 bits | 1 to 6 ms |
| A whole handshake's certificate checks | 10 to 90 ms |

A good chain is remembered, so the second connection to a site does
not check it again.

## How it is tested

`tests/browser.sh` (run by `tests/run.sh browser`) builds
`tests/browser/check.omg`, a program that exposes each part on the
command line, and asks it 55 things. Nothing in it needs the network
or a screen.

- **Ciphers and hashes**: 101 vectors in `tests/browser/vectors.txt`,
  from the RFCs and NIST where they give them, and otherwise worked
  out with Python's `cryptography` package: every hash, HMAC, HKDF,
  both ciphers (with tampered messages that must be refused), X25519,
  both curves, ECDSA and RSA checks that must pass and that must fail.
- **Certificates**: 14 cases against a small authority made for the
  tests (`tests/browser/pki/`), with the clock fixed: a good chain,
  wildcards, an IP address, the wrong host, a root nobody vouched for,
  a certificate from the future and one that ran out, a chain with a
  link missing, a certificate with one bit changed, one signed by a
  certificate that may not sign, RSA-PSS, and a self-signed
  certificate off and on the list.
- **Addresses, HTML, unpacking**: files of cases with the wanted
  answers beside them in `tests/browser/want/`.
- **Pictures**: nine files covering the kinds of PNG, GIF and JPEG,
  each decoded and its pixels compared by checksum. The PNG and GIF
  checksums are those of what Pillow decodes; the JPEG ones are this
  decoder's own, kept after its pixels were seen to be within 2 of
  Pillow's, since JPEG decoders may round differently.
- **Layout**: a page laid out 800 and 400 pixels wide, the place and
  size of every box compared with a list.
- **The whole thing**: a page drawn with `--screenshot` and the
  checksum of the picture compared. The page holds no text, so the
  picture does not depend on which fonts a machine has. The Windows
  build, run under Wine, gives the same checksum.
- **HTTP**: `tests/browser/server.omg`, a small server in OMG, answers
  with a length, in chunks, gzipped, with redirects (and a loop of
  them), cookies, and by closing; `check fetch` must get each right.
- **TLS**: `openssl s_server` is started with keys made on the spot,
  eleven times: both versions, each cipher, ECDSA and RSA
  certificates, servers that insist on P-256 or P-384, and one that
  asks for a client certificate. A page is fetched through each.
  Servers that offer only TLS 1.1, only RSA key exchange, or a
  certificate nobody vouches for must be refused. Skipped where
  `openssl` is not installed.

Beyond the suite, the browser was pointed at some fifteen real sites
while it was written (Wikipedia, Hacker News, the BBC, MDN, python.org,
gnu.org, DuckDuckGo and others), which is where most of the layout
fixes came from. Each gave a certificate chain that checked against
the built-in authorities.

## What is not there

- **JavaScript.** Pages that build themselves with scripts show what
  their HTML holds, which for some is nothing. `<noscript>` content is
  shown.
- **SVG and WebP pictures**, and so many logos and icons. Animated
  GIFs stand still. No video or sound.
- **HTTP/2 and HTTP/3.** Every server asked so far still speaks 1.1.
  Pictures are fetched one at a time over one connection.
- **In TLS**: no check of whether a certificate has been revoked, no
  name constraints, no session resumption, no client certificates, and
  arithmetic that is not constant-time. IPv6 addresses are not
  understood.
- **In CSS**: `:hover` and the other states that change as the page is
  used never match; no animations, transitions or transforms; no
  `@font-face` (letters come from the system's fonts); no shadows;
  gradients are not clipped to rounded corners; grid has columns but
  not named areas or row templates; a box with `overflow: scroll`
  grows to hold its content.
- **In HTML**: misnested tags are closed simply, not by the standard's
  full algorithm; no frames or iframes.
- **In the window**: no tabs, bookmarks or downloads; no selecting
  text on the page and no search in it; text is laid out left to right
  only. Nothing is cached on disk and nothing is remembered after the
  browser closes.
- **On Windows**, the build is tested without a window (files, HTTP,
  and the screenshot checksum, under Wine). The window itself uses the
  same builtins as the video player, but the browser has not been
  driven by hand there.
